# الفحص النهائي لتحديد المدينة — 2026-11-09

**القرار: لا أوصي بالنشر حاليًا.** فحص الهاتف الحقيقي كشف أن الاكتشاف التلقائي لم ينجح في تجربة دورا، وأن API الإنتاج لا يدعم الميزة بعد. لم يُنشر Flutter أو Laravel ولم تُعدّل ملفات أو بيانات الإنتاج.

## بيئة الفحص

- هاتف Android حقيقي متصل عبر USB، موديل OPPO CPH2217، وليس محاكيًا.
- أكد المستخدم أن الموقع الفعلي للهاتف هو **دورا**. لم تُستخدم إحداثيات وهمية أو موقع GPS مصطنع.
- بُني APK Debug بنجاح، موصولًا بـ Laravel المحلي باستخدام `API_BASE_URL=http://localhost:8000/api` وADB reverse.
- اختبارات الإنتاج كانت قراءات GET عامة فقط؛ لم تُجر عمليات تسجيل أو حفظ أو تحديث أو إنشاء طلب على الإنتاج.
- حُفظ APK الهاتف الأصلي ونسخة خاصة من بيانات Hive على الهاتف قبل الاختبار. لم تُحذف بيانات التطبيق أو يُنفذ `pm clear`.

تم التأكد من انقطاع الإنترنت على Android نفسه: `Active default network: none` وWi-Fi متوقف. أُوقف اتصال USB المحلي بالـ API أيضًا أثناء تجربة الفتح دون اتصال؛ ثم أُعيدت الشبكة والوصلة لاختبار الاستعادة.

ظهور «دورا» في خطوات مبكرة لم يُعتبر دليل نجاح للاكتشاف التلقائي، لأن المستخدم كان يتفاعل مع الهاتف حينها. بعد تنسيق ترك الهاتف للفحص، أُزيل **مفتاح اختيار المدينة فقط** مؤقتًا مع الحفاظ على بقية البيانات، ثم فُتح التطبيق دون أي ضغط داخله. فشل تأكيد المدينة في هذه التجربة، وهي النتيجة المعتمدة لهذا التقرير.

## سبب فشل الاكتشاف التلقائي في دورا

استُخدم راوتر تشخيص محلي مؤقت خارج كود المشروع؛ لم يُعدل `CityLocationResolver` أو أي صلاحيات. سجل التشخيص بيانات النتيجة فقط دون إحداثيات العميل أو عنوانه أو رموز دخوله:

```json
{
  "accuracy_metres": 24.899999618530273,
  "http_status": 200,
  "resolved_city": null,
  "provider_cache_present": true,
  "osm_type": "node",
  "address_type": "village",
  "geometry_type": "Point",
  "country": "ps",
  "approved_name_match": null,
  "contains_point": false,
  "contains_accuracy": false
}
```

دقة GPS هنا نحو **25 مترًا**؛ ليست المشكلة رفض الإذن أو ضعف دقة يتجاوز شرط 100 متر أو انقطاع خدمة المزود. وصلت استجابة المزود وتخزنت، لكنها كانت نقطة لقرية، دون مضلع مدينة أو مطابقة اسم معتمد. التنفيذ الحالي يقبل Polygon/MultiPolygon فقط مع إثبات الاحتواء، لذلك أعاد `city: null` بدل تخمين مدينة خاطئة.

**المطلوب قبل اعتبار الاكتشاف جاهزًا:** تحسين ربط الموقع بحدود المدن المعتمدة، بإحضار/تخزين حدود حقيقية ومعرّفات موثوقة ومطابقتها هندسيًا. لا يكفي قبول اسم أقرب قرية أو أقرب متجر. يجب إعادة اختبار دورا فعليًا بعد المعالجة، ومدن أخرى وحدود المدن، مع الالتزام بقيود خدمة الخرائط. لم تُنفذ هذه المعالجة في جولة الفحص الحالية.

## توافق API المنشور

قراءة `https://elitecleanps.com/api` أثناء الفحص أظهرت:

| الطلب | النتيجة |
|---|---|
| `GET /cities` | **404** |
| `GET /vendors` | **200**، متجران، الحقول الحالية العشرة موجودة، دون `city` أو `city_id` |
| `GET /vendors?city_id=city_1676f59bc3403916594c` | **200**، نفس المتجرين؛ فلتر دورا لا يُطبق |
| `GET /services?city_id=invalid` | **200** بدل 422 الذي يتطلبه العقد الجديد |
| `GET /products?city_id=invalid` | **200** |
| `GET /offers?city_id=invalid` | **200** |
| `GET /promotions?city_id=invalid` | **200** |
| `GET /banners/wide?city_id=invalid` | **200** |

عدم وجود `city` في JSON لا يثبت أن العمود فارغ في قاعدة الإنتاج؛ العمود موجود وفق الفحص السابق لكنه غير معروض في API الحالي. لم تُعدّل بيانات المدينة في الإنتاج.

**Flutter الجديد غير متوافق وظيفيًا مع API المنشور لميزة المدن.** طلب `/cities` سيفشل، فتظهر رسالة تحميل المدن ويتوقف عرض محتوى المدينة. يلزم نشر Backend **أولًا** بعد معالجة مشكلة الاكتشاف وإعادة الاختبار؛ ثم التحقق من قائمة المدن والإحداثيات والفلاتر واستجابات التطبيق القديم قبل إصدار Flutter. وجود عمود `city` في الإنتاج يعني أن هذه الميزة لا تحتاج Migration جديدة وفق الفحص السابق، مع إعادة التأكد عند أي نشر لاحق. لا ينبغي تشغيل جميع ترحيلات المشروع دفعة واحدة لهذه الميزة.

## العنوان المحفوظ والسلة والطلبات

- قورنت SHA-256 لملفات Hive قبل الاختبار وبعد تغيير المدن وإغلاق التطبيق واختبارات الفشل: ملفات **السلة والحساب وبيانات المستخدم مطابقة تمامًا**.
- مقارنة إعدادات التطبيق مع استثناء مفتاح المدينة أظهرت تغير المفتاح `tracking_recovery_available` فقط، بسبب قراءة إعدادات Backend المحلي؛ لم تظهر تغييرات أخرى في قيم الإعدادات. ليست هذه صلاحية حساب أو تعديلًا في العناوين.
- اختيار المدينة يكتب في `home_city_choice_v1` فقط؛ لا يكتب `address_id` ولا يعتمد عليه مزود جلسة العنوان.
- لم تُحفظ عناوين أو تُعدّل عناوين أو تُنشأ طلبات أثناء الفحص، ولم تُرسل عمليات كتابة إلى إنتاج الطلبات أو الأسعار أو رسوم التوصيل.
- **حد التحقق:** لم يُنفذ طلب حقيقي بعنوان محفوظ عبر Checkout. فتح صفحة الطلبات بالحساب الموجود على Backend المحلي أظهر `Unauthorised request`؛ لذلك لا أعدّ هذه الجولة اختبارًا كاملًا لحساب العميل وطلباته على الإنتاج. عدم تغيير الملفات ومراجعة الاعتماديات دليل عزل اختيار المدينة، وليس بديلًا عن اختبار Checkout متكامل على بيئة فحص مطابقة.

## اختبار Laravel الفاشل

أُعيد تشغيل `CityHomeTest` و`AdminManagementTest` عبر `phpunit.city.xml` على SQLite المعزول:

**14 اختبارًا، 106 تحققات، إخفاق واحد**؛ اختبارات المدن الستة نجحت.

السبب محدد:

- `tests/Feature/AdminManagementTest.php:67` يتوقع `$admin->hasRole('admin')`.
- `app/Http/Controllers/Web/Root/AdminController.php:54` ينفذ `assignRole($this->resolveRootRole())`.
- `resolveRootRole()` يعيد دور `root`؛ وهذا موضح في تعليقات التنفيذ الحالي للمشرفين.

إذًا توقع الاختبار لا يطابق سلوك إنشاء المشرف الحالي؛ الإخفاق لا يأتي من ميزة المدن. **لم تتغير أدوار أو صلاحيات النظام أو الاختبار** لإخفاء الإخفاق. أي تعديل لاحق لتوقع الاختبار يجب أن يستند إلى سياسة الأدوار المعتمدة، دون تغيير صلاحيات الإنتاج كجزء من هذه الميزة.

إعداد الاختبار المعزول يستثني ترحيلَي ENUM القديمين الخاصين بـ MySQL كما هو موثق في تقرير التطوير؛ لم تُعدل ترحيلات الطلبات. نتائج Flutter الآلية السابقة كانت 64 اختبارًا ناجحًا؛ لم تُستبدل نتائج الهاتف الفعلية بهذه النتائج الآلية.

## المشاكل المتبقية وترتيب المعالجة

1. **مانع جاهزية:** فشل تأكيد دورا تلقائيًا مع نتيجة مزود من نوع Point؛ يلزم مصدر حدود معتمدة أو تحسين التحقق الجغرافي ثم اختبار ميداني جديد.
2. **مانع إصدار Flutter:** Backend المنشور لا يدعم واجهات المدن والفلاتر والحقول الجديدة. يجب نشر Backend بإذن مستقل قبل Flutter وبعد معالجة المانع الأول.
3. **اختبار تكامل غير مكتمل:** يلزم بيانات متاجر فعلية مرتبطة بمدن وإحداثيات صحيحة في بيئة الفحص، لاختبار ظهور المنتجات والخدمات والدبابيس وفتح صفحات المتاجر على الهاتف.
4. **العمل دون اتصال:** الاحتفاظ باسم آخر مدينة معتمدة وقائمة مدن مخزنة سيسمح بعرض الاختيار المحفوظ؛ حاليًا تُطلب القائمة من الشبكة قبل الاستعادة. الاختيار لا يُمح، لكنه لا يظهر أثناء الانقطاع.
5. **نصوص تجربة المستخدم:** رسائل توقف/رفض الموقع تستخدم نصوص العناوين القديمة مثل «اختر عنوانًا محفوظًا» و«اختر نقطة على الخريطة»، رغم أن المستخدم داخل اختيار المدينة؛ يلزم نص خاص بالمدينة.
6. **اختبار منفصل:** توقع دور `admin` في اختبار إدارة المشرفين لا يطابق `root` في التنفيذ الحالي.
